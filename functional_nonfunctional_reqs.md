Functional Requirements:  
1. The system must operate locally with and users are allowed to create and log in to their accounts using a username and password.  
   
2. The system shall display the location, capacity and status of all UWI busses.  
   
3. The system shall display all bus stops along the UWI bus route on an interactive map and display the number of requests at each stop.  
   
4. The system must allow users to filter bus stops along the route by requests for different time slots.  
   
5. The system shall notify the user when a time slot has reached its request threshold.  
   
6. The system must display a report detailing statistics such as “ Total requests, passengers transported, average passengers,etc”  
   
7. The system must generate a new bus schedule for the next day based on data up to a year ago.  
   
8.  The system should notify users of when a decision was made on a request to simulate sending notifications to passengers.  
   
9. The system should notify users in real time and report and report any issue that has occurred mid transport.  
   
   
Non-Functional Requirements:  
1. The system should be designed to respond to user actions within 2 to 3 seconds eg. Viewing requests, allotting available busses to departure times, sending response notifications, etc  
   
2. The system should be able to handle at least 1,000 concurrent requests without fail.  
   
3. The system must allow for additional server capacity to be added when required.  
   
4. The system must maintain a 99.9% uptime and a notification for maintenance must be provided at least 24 hours prior.  
   
5. User passwords and sensitive data should be encrypted using industry standard encryption methods  
   
6. Users must be automatically logged out after 30 minutes of inactivity.  
   
7. System shall ensure submitted reports are secured from unauthorised access and backed up every 24 hours.  
   
8. The system should allow for easy updates and debugging without hindering expected functionality.  
   
9. The system must be designed to adapt to different devices without issue such as phone, tablet, laptop etc.  
   
10. Any errors displayed by the system should be user-friendly and logged for debugging.  
   
11. The system must have a well-documented code to support future error fixing and debugging.
